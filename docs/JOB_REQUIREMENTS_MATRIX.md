# Job requirements matrix: IT Manager (AMS Technology Solutions posting)

This matrix maps each requirement in one public job posting to artifacts that exist in this repository. It was compiled on 2026-10-28 (America/New_York). Every requirement is labeled with exactly one coverage status. It is a preparation aid. It is **not** evidence of employment history, management tenure, production operations, or certification.

## Posting source

- **Posting:** "Information Technology Manager", AMS Technology Solutions LLC, Boston (MA), Hybrid, Full time, USD 120,000–190,000. Retrieved 2026-10-28 from JobLeads: <https://www.jobleads.com/us/job/information-technology-manager--boston--e57b1e5ed0b5b152dff0ddd60c8e955b2> (schema.org `datePosted` 2026-10-27).
- The text describes the employer only as "the Bank". This document does not name the bank, because no evidence verified here establishes who it is.
- No posting text exists anywhere in this repository. The requirement wording below either quotes the posting or paraphrases it closely.
- **Role context, from the posting:** 70–80% hands-on senior engineering and 20–30% management (team and vendors). The role leads 8–10 staff across helpdesk, network/infrastructure, and cloud. It expects a hybrid background: traditional on-prem infrastructure first, then 4–5 years in cloud. Strong AWS operations are critical. Financial or banking experience is a plus but not mandatory.

## What the lab is, and what it is not

- `main` (`7f50348`) contains only `README.md`. All lab work is in **draft PRs** [#1](https://github.com/onnxscibroccoli/bank-it-operations-lab/pull/1)–[#8](https://github.com/onnxscibroccoli/bank-it-operations-lab/pull/8). Nothing has been merged into `main`. No PR has a formal human GitHub review.
- **Nothing is deployed.** No AWS, Entra ID, or Microsoft Graph API was called. AWS work is credential-free `tsc`, Jest, `cdk synth`, and cdk-nag. Entra work validates synthetic JSON policies offline. The one *executed system* demonstration is the PostgreSQL backup/restore exercise, which runs against real PostgreSQL 16 servers in GitHub Actions (service container) and in a sandbox.
- All lab artifacts are dated 2026-10-28. They show what the lab contains and what its CI executes. They do not show how long anyone has done this work, or that anyone has done it for an employer. Where AI tooling helped produce an artifact, say so in an interview, and be ready to walk through and re-run it yourself.

### Coverage legend

- **demonstrated**: the lab *executes* it, and committed evidence or a green CI run at a cited commit records the execution (for example, a real `pg_restore` against a running server, or a CI pipeline that ran).
- **static reference**: code, configuration, or design exists and was checked offline (synth, tests, linters, validators), but it was never deployed or operated.
- **partial**: some of the requirement is covered by demonstrated or static artifacts, and a material part is not.
- **missing**: no lab artifact. This includes requirements a lab cannot show by nature: years of experience, people management, vendor relationships, degree, certifications, and physical conditions. The limitation column flags these as *not lab-demonstrable*.
